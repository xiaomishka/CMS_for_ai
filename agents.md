# agents.md — спецификация для ИИ-адаптации HTML-шаблонов

> Этот файл предназначен для ИИ-агентов, которые адаптируют готовые HTML-шаблоны под CMS_for_ai.
> Читай целиком перед началом работы. Ядро CMS трогать нельзя — адаптация заключается в создании
> новой папки темы `templates/<имя>/` и, при необходимости, простых плагинов.

---

## 1. Принцип работы

CMS — легковесная, без composer, на PHP 8.1+ + RedBeanPHP (один файл `core/rb.php`).
Главная фишка — szybкая адаптация любого HTML-шаблона силами ИИ:

- Папка темы: `templates/<имя>/` с файлами `*.tpl` (теговый шаблонизатор) или `*.phtml` (чистый PHP).
- `theme.json` — метаданные темы: имя, версия, движок (`"tpl"` по умолчанию или `"phtml"`), список слотов.
- Точка входа: один `index.php` + `.htaccess` (все URL через роутер из таблицы `routes`).
- Шаблоны компилируются ядром в PHP-кэш (`core/cache/`). ИИ не компилирует вручную.

**Юридическая чистота:** синтаксис тегов (`{{ ... }}`, `[each]`, `[if]`, `[include]`, `[slot]`) осознанно не копирует DLE. Оригинальный код парсера — свой. ИИ меняет только разметку темы, не трогает ядро.

## 2. Карта файлов темы (§4.3 ARCHITECTURE.md)

```
templates/<имя>/
├── theme.json          # метаданные (обязательно)
├── layout.tpl          # общий каркас сайта (обязательно)
├── view.article.tpl    # полная статья
├── view.category.tpl   # рубрика со списком статей
├── view.page.tpl       # статическая страница
├── list.home.tpl       # главная страница (список статей)
├── partial.news.tpl    # анонс статьи в циклах (опционально)
├── partial.sidebar.tpl # сайдбар (опционально)
├── 404.tpl             # страница «не найдено»
├── 500.tpl             # ошибка сервера (опционально)
└── assets/             # css, js, картинки темы
```

Маппинг «страница → шаблон» задаётся в `theme.json` и используется ядром через `View::renderPage('имя', $ctx)`.

## 3. theme.json

Пример:

```json
{
    "name": "My Theme",
    "version": "1.0",
    "engine": "tpl",
    "slots": ["head", "before_end"],
    "description": "Описание темы для адаптации HTML-шаблона"
}
```

| Поле | Назначение |
|------|------------|
| `name` | Название темы (показывается в настройках админки) |
| `version` | Версия темы |
| `engine` | `"tpl"` — теговый шаблонизатор (по умолчанию), `"phtml"` — чистые PHP-шаблоны |
| `slots` | Список имён слотов для плагинов (`[slot head]` в layout) |
| `description` | Описание |

Режим `phtml` — для форков, там данные приходят как `$view->...`, хелперы `$view->e()`, `$view->raw()`, `$view->slot()`, `$view->inc()`.

## 4. Реестр тегов шаблонизатора tpl (§4.2)

### 4.1 Переменные — `{{ ... }}`

| Тег | Значение |
|-----|----------|
| `{{ site.name }}` | Простая подстановка (авто-экранирование HTML) |
| `{{ article.full|raw }}` | Вывод без экранирования (только для надёжного HTML-контента) |
| `{{ article.date|date:"d.m.Y" }} | Модификатор: `date`, `truncate:"N"`, `upper`, `lower`, `raw` |

Авто-экранирование применяется ко всем `{{ ... }}` кроме `|raw`.

### 4.2 Блоки — `[...] ... [/...]`

| Тег | Назначение |
|-----|------------|
| `[each articles as a] ... [/each]` | Цикл по массиву. Внутри доступны переменные с префиксом `a.` |
| `[each list as a] ... [else] ... [/each]` | Блок `[else]` выводится, если массив пуст |
| `[if a.cover] ... [/if]` | Условие (truthy). Поддержка: `not a.cover`, `a.status == "published"`, `!=`, `>`, `<`, `>=`, `<=` |
| `[if user.can("article.edit.any")] ... [/if]` | Проверка прав пользователя из шаблона |
| `[if user.logged] ... [/if]` | Пользователь авторизован |
| `[include partial.sidebar]` | Вставка другого `.tpl` того же контекста |
| `[slot head]` | Точка вывода плагинов (хук `template.slot:head`) |
| `[# комментарий #]` | Удаляется при компиляции |

### 4.3 Данные в циклах и контексте

Каждая статья в цикле `[each articles as a]` содержит поля:

- `a.id` — ID статьи
- `a.title` — заголовок
- `a.slug` — URL-slug
- `a.url` — полная ссылка на статью (согласно схеме ЧПУ)
- `a.short` — короткое описание (анонс)
- `a.full` — полный текст (HTML)
- `a.cover` — URL обложки (пусто, если нет)
- `a.date` — дата публикации (YYYY-MM-DD HH:MM:SS)
- `a.edited` — дата редактирования
- `a.meta_title`, `a.meta_description` — SEO
- `a.category` — объект `{id, title, slug, url}` или `null`

Общий контекст страниц (всегда доступен):

- `site.name`, `site.url`, `site.year`
- `meta.title`, `meta.description`
- `nav` — массив `{title, url}` корневых рубрик
- `recent` — последние 8 опубликованных статей `{title, url, date}`
- `user` — `{name, role, logged}` (гость: `logged = false`)

## 5. Правила адаптации HTML-шаблона

1. **Создай папку темы:** `templates/<имя>/` (имя в нижнем регистре, только латиница, цифры, подчёркивание).
2. **Скопируй assets** (CSS, JS, картинки) из исходного HTML-шаблона в `templates/<имя>/assets/`.
3. **Нарежь один HTML-файл на шаблоны:**
   - общий каркас (header + footer) → `layout.tpl`, контентная зона заменяется на `{{ content|raw }}`;
   - страница статьи → `view.article.tpl`;
   - страница рубрики → `view.category.tpl`;
   - статическая страница → `view.page.tpl`;
   - главная → `list.home.tpl`;
   - повторяющиеся блоки (сайдбар, карточка новости) → `partial.*.tpl`.
4. **Замени статичный контент на теги:**
   - Названия сайта → `{{ site.name }}`
   - Ссылки рубрик → цикл `[each nav as n] <a href="{{ n.url }}">{{ n.title }}</a> [/each]`
   - Список статей → `[each articles as a] ... [/each]` с полями `a.title`, `a.url`, `a.short`, `a.cover`, `a.date`
   - Обложка статьи → `[if a.cover]<img src="{{ a.cover }}">[/if]`
   - Полный текст → `{{ article.full|raw }}`
5. **Добавь слоты для плагинов:** `[slot head]` в `<head>` layout, `[slot before_end]` перед `</body>`.
6. **Напиши `theme.json`** с `"engine": "tpl"` и списком слотов.
7. **Проверь:** выбери тему в настройках админки, открой главную, статью, рубрику, 404.

## 6. Режим вебархива (восстановление иерархии старых URL)

Если адаптируешь старый сайт:

1. Сохрани исходную иерархию URL в таблице `routes` через админку или прямо в БД.
2. Поле `pattern` — шаблон URL со слотами `{slug}`, `{cat}`, `{n}`.
3. Поле `target` — контроллер: `article.view`, `category.view`, `page.view`, `home`, `feed.rss`, `feed.sitemap`.
4. Поле `redirect_to` + `status` (301/302) — для перенаправления старых адресов на новые.
5. `priority >= 100` — кастомные роуты сохраняются при смене пресета ЧПУ; дефолтные (priority < 100) перезаписываются.

Пример: `pattern=/blog/{slug}.html`, `target=article.view`, `priority=100`.

## 7. Правила кода ядра (для форков)

1. **Никакого composer.** Всё подключается `require` / `require_once`.
2. **Whitelist-заполнение бинов.** Данные из `$_POST` никогда не попадают в `R::import()` — только явное присваивание полей (см. `admin/index.php:article_save`).
3. **Схема заморожена после установки:** `R::freeze(true)`. Новые таблицы/колонки — только через миграции (`Database::migrate()`) в fluid-режиме.
4. **Имя бина (таблицы):** только `[a-z0-9]+`, подчёркивания запрещены. Колонки с `_` разрешены.
5. **Исключения с namespace:** ловить `catch (\Throwable)` — без слэша это `Controllers\Throwable`.
6. **CSRF на всех POST-формах админки:** `Auth::csrfField()` в форме, `Auth::csrfCheck()` в начале case.
7. **Права:** проверять через `Auth::can("perm")` перед любым действием в админке.
8. **`bootstrap.php` и `install.php`:** только `require_once` + guards на `define` (выполняются дважды на встроенном сервере PHP).
9. **Не перезатирать `core/rb.php`** — там пропатчена константа `RB_PDO_MYSQL_ATTR_INIT_COMMAND` через fallback 1002.
10. **Runtime-файлы** (`core/config.php`, `core/*.sqlite`, `core/cache/`, `*.log`, `install.done.php`) — не часть пакета, не в git.

## 8. Чек-лист перед завершением адаптации

- [ ] `theme.json` корректен, `engine` указан
- [ ] Все обязательные tpl-файлы на месте
- [ ] `{{ content|raw }}` присутствует в `layout.tpl`
- [ ] `[slot head]` и `[slot before_end]` есть в layout
- [ ] Ассеты лежат в `assets/` и ссылки на них верны
- [ ] Тема выбрана в настройках админки, сайт открывается: `/`, статья, рубрика, 404
- [ ] HTML валиден, нет жёстко зашитых путей к старой теме
